# LearnFlow 第一版设计草案

日期：2026-10-23  
状态：待用户确认；本文件是产品和技术设计，不代表已经实现或创建 Figma 设计稿。

## 1. 目标与已知约束

用户正在学习新知识，核心困难是资料分散、学完容易忘、每天不知道学什么。第一版把学习计划、知识笔记、间隔复习整合为一个个人学习闭环：收集资料 → 拆解计划 → 今天学习 → 整理笔记与问题 → 到期复习 → 调整计划。

用户已确定 Vue 3 + TypeScript + FastAPI + PostgreSQL + Figma，要求前后端完整、组件现代且可复用、便于迭代。

以下是本草案由设计者提出的默认选择，尚未视为用户已确认：个人本地使用、中文、桌面浏览器优先、小屏可完成核心操作、单一工作空间、默认每天 45 分钟、时区 Asia/Shanghai。每日时长、每周学习日、时区可在设置中修改。第一版不接入收费服务。

成功标准：能把一个真实主题的资料集中起来，拆出可执行任务，连续使用一周，每天无需重新规划即可开始；复习内容来自自己的笔记，关闭浏览器和重启服务后数据仍在。效率改善通过使用反馈验证，不承诺特定记忆效果。

## 2. 第一版功能边界

| 模块 | 第一版包含 | 暂不包含 |
| --- | --- | --- |
| 学习主题 | 标题、目标、优先级、状态；暂停与归档 | 课程市场、团队空间 |
| 资料库 | 链接或文本摘录、标题、来源、主题、阅读状态；关键词搜索 | 文件上传、PDF 解析、网页抓取、浏览器插件 |
| 学习计划 | 手动拆分任务、顺序、预计分钟数、可选计划日期、完成与跳过 | AI 自动生成课程、复杂依赖、日历同步 |
| 知识笔记 | Markdown 编辑与预览、关联主题及可选资料、手动保存、标题和正文搜索 | 富文本协作、知识图谱、附件 |
| 复习卡 | 问题、答案、来源笔记；从笔记选段预填答案并手写问题；独立编辑、暂停 | AI 自动出题、多种题型、共享题库 |
| 间隔复习 | 到期队列、先问题后答案、三级反馈、持久化复习记录 | 个性化记忆模型、推送通知 |
| 今日学习 | 每日时间预算、复习与任务建议、直接开始、完成情况、手动调整 | 番茄钟、积分、连续打卡压力机制 |
| 数据与设置 | 每日时长、学习日、时区；主题数据 JSON 导出及笔记 Markdown 导出 | 应用内导入恢复、跨设备同步 |

不以收藏数量或笔记数量代表掌握程度；不把“读完资料”自动当作“记住知识”。完成任务与知识复习相互关联，但状态独立。

## 3. 一次完整使用流程

1. 创建“学习 Vue 3”主题，写下目标“能独立完成一个带接口的页面”。
2. 添加文档、课程链接、摘录，资料归入主题。
3. 拆成“理解响应式”“练习组件通信”等任务，设置顺序和预计时长。没有任务时提示先拆一个小任务，不生成虚构计划。
4. 打开今日学习：查看到期复习和建议学习任务。每项显示原因，例如“已到复习日”或“主题优先级高、顺序最靠前”。
5. 开始任务，在应用内打开笔记，资料链接在外部新标签页打开。学习完成后手动完成任务，资料阅读状态独立调整。
6. 保存笔记后创建一张或多张问答卡，例如“ref 与 reactive 的差别是什么”。建立卡片不是完成任务的强制条件。
7. 到期后只显示问题，用户先自行回忆，再展示答案，选择“忘记 / 模糊 / 记住”。反馈后显示下次复习日期。
8. 没完成的任务保持待办，下一次建议重新计算；历史完成记录保留。

## 4. 今日安排的明确规则

第一版使用可解释的确定性规则，不引入 AI 排程服务。

- 时长预算是建议值，不阻止超额学习。每天默认为 45 分钟；复习卡估算 2 分钟，可用于预算计算，不冒充真实学习耗时。
- 当日已完成任务以完成时的预计分钟数快照计入已用预算，每次复习反馈计 2 分钟；剩余预算为总预算减已用估时，最低为零。建议只分配剩余预算，避免完成后不断补充新任务；预算耗尽时仍可手动继续。完成事件按当前设置时区换算归属日，时区修改后当前日统计重新计算，历史事件保留当时本地日期供审计。
- 到期复习优先：按到期时间从早到晚、卡片 ID 排序；只取活动主题且未暂停的卡。`due_at <= 当前时间` 即到期，UTC 存储，按用户时区显示。
- 有复习时默认最多预留预算的 40%，至少容纳 1 张卡（最低每日预算 5 分钟）。到期卡超出建议数量时显示“还有 N 张待复习”，用户可继续；逾期不会重置或隐藏。
- 无复习时全部预算给学习任务；不足一张复习卡的剩余预算不占用。复习估时从总预算扣除后再选择新任务。
- 新任务只从活动主题的未完成任务中取：计划日期不晚于今天的优先，较早日期先；其后为未指定日期任务；相同组内按主题优先级、主题创建时间、主题内顺序、任务 ID 排序。未来日期任务不提前推荐。
- 顺序扫描并选择可放入剩余预算的任务；放不下的保留在待办。若没有任何任务能放入且剩余预算大于零，推荐排名最前的一项并明确“预计超出今日预算”，用户可手动拆分。
- 任务排序不表达依赖；用户若要求严格先后，第一版通过调整计划日期实现，不偷偷跳过依赖推断。
- 非学习日不生成新任务建议；到期复习仍显示为可选，不强制休息日学习。允许手动加入任务或继续复习。
- “今天跳过”只影响该日建议，不改变原任务及卡片的到期时间；跳过记录跨刷新保留，次日自动失效。用户可恢复已跳过项。
- 今日建议按当前待办动态计算；手动加入和跳过以用户本地日期存储。完成情况来源于学习及复习记录，不因重新计算丢失。
- 暂停主题会停止推荐其任务和卡片；恢复后保留原到期时间。归档主题只读并退出建议、复习队列，恢复后可再次编辑。

用户可以明确知道为什么排到某项，也可以跳过或调整，避免让自动计划变成额外负担。

## 5. 间隔复习 v1

第一版采用自定义固定间隔策略，目的是规则简单、可解释、可测试；不称为 SM-2 或 FSRS。复习算法作为独立服务，以策略名称和版本持久化，为以后替换保留接口。

- 一张卡包含一个问题、一份答案、可选来源笔记。新卡立即到期，可在当天第一次复习。
- 阶段依次为 1、3、7、14、30、60 天；新卡阶段为 -1。
- “记住”：阶段增加 1，最多到阶段 5；按新阶段对应天数排下次。到顶后每次记住仍为 60 天。
- “模糊”：阶段不变，下一次为 1 天后；新卡仍为 -1。
- “忘记”：阶段重置为 -1，10 分钟后重试。重试前可先完成其他卡，无卡可复习时显示下次时间，不要求等待。
- 间隔从提交反馈的实际时间计算，统一以 UTC 时间加固定时长（天按 24 小时）；界面展示本地日期和时间。该规则不依赖浏览器处于打开状态，也不需要后台定时任务。
- 每次提交保存评分、发生时间、原阶段、新阶段、下次时间及策略版本。同一卡反馈须在数据库事务中串行处理；每次提交带唯一幂等键及卡片版本，网络重试不重复记账，多标签页旧版本返回冲突并刷新。
- 显示答案本身不改变排程；未提交评分就离开不算完成。评分失败保留当前卡并允许重试，不能先显示成功。
- 编辑答案不自动清空复习历史；用户可显式重置卡片，生成重置事件并恢复到 -1、立即到期。已复习卡支持暂停，不提供破坏历史的永久删除；未复习卡可以删除。
- 不提供评分撤销，避免第一版回滚排程复杂化；提交前按钮有清晰标签，提交后显示下一日期。

## 6. 页面与 Figma 交付

一级入口控制在：今日学习、学习主题、资料库、知识笔记、复习；设置放在次级入口。以下是页面职责，不是已绘制的 UI。

| 页面 | 核心职责 | 必须覆盖的状态 |
| --- | --- | --- |
| 今日学习 | 时间预算、建议原因、开始/完成/跳过、剩余复习量 | 首次使用、无任务、超预算、完成今日、请求失败 |
| 主题列表与详情 | 目标、资料、任务排序、主题下笔记与卡片 | 空主题、暂停、归档、保存失败 |
| 资料库 | 链接与摘录收集、主题/阅读状态筛选、搜索 | 无结果、无效链接、外链打开 |
| 笔记列表与编辑 | Markdown 编辑预览、关联来源、创建复习卡 | 未保存、保存中、已保存、保存失败、并发冲突 |
| 复习界面 | 问题 → 自行回忆 → 展示答案 → 评分 | 无到期卡、暂停卡、提交失败、等待重试、旧版本冲突 |
| 设置与导出 | 每日时长、学习日、时区、主题 JSON/笔记 Markdown 导出 | 输入错误、导出中、失败 |

Figma 计划分为 Foundations、Components、Screens、Flows 四个部分，包含语义色、字号、间距、圆角、阴影及交互状态；采用 Auto Layout、组件变体和统一命名。先设计默认明亮主题，深色模式放入后续迭代。

设计顺序：用户流程 → 今日学习/笔记/复习低保真 → 基础组件与设计变量 → 高保真与可点击闭环 → 其他页面及空态/错误态 → 开发交付。桌面基准 1440px，同时检视 390px 的核心流程。

Figma 与代码共享语义 Token，例如 primary、surface、text、muted、danger；以代码 CSS 变量实现映射，在 `docs/design/component-map.md` 记录 Figma 组件名、Vue 组件和变体对应。UI Kit 只作为起点，核对版本与许可后使用，不默认购买付费资源。

当前已发现可连接的 Figma 插件，尝试发送连接建议时网络请求失败，尚未确认连接，也未创建文件。接入后核对实际工具是否支持创建/编辑所需设计。Figma 是用户指定交付工具，连接和写入能力属于第一阶段的外部依赖；能力不足时不能视为该阶段已验收，也不自行改为其他原型工具。可先完成流程说明、Token 清单、组件映射等独立准备；若仍需用户连接或操作，再说明已验证的具体缺口。

## 7. 技术与模块边界

前端：Vue 3、TypeScript、Vite、Vue Router；以 shadcn-vue 为基础，配合 Tailwind CSS、Lucide 图标；服务端状态由 TanStack Query 管理，Pinia 仅用于确有需要的跨页本地状态。Markdown 使用成熟渲染库，禁用原始 HTML 并对外链协议作限制。具体兼容版本在实现时核查并锁定，不在草案中猜版本。

选择 shadcn-vue 的原因是组件源码可纳入项目，便于统一样式与渐进修改；维护升级也由项目承担。基础 UI 放 `components/ui`，业务组件放 `components/learning`，页面不直接复制整段业务交互。

后端：FastAPI、Pydantic、SQLAlchemy、Alembic、PostgreSQL；REST API 使用 `/api/v1`。按 settings、topics、resources、tasks、notes、reviews、today、exports 模块组织。路由负责输入输出，服务处理排程和业务事务，数据访问与业务规则分离；不引入微服务、Redis 或任务队列。

通过 FastAPI OpenAPI 生成 TypeScript API 类型或客户端；契约检查发现接口漂移。错误结构统一包含可读信息、错误码、字段错误及请求 ID。列表有分页；文本搜索第一版用 PostgreSQL 参数化子串查询，覆盖中文标题/正文，无外部搜索服务。

建议仓库布局：

```text
apps/web/                 Vue 前端，按 features 组织业务
apps/api/                 FastAPI、领域服务、数据库迁移、测试
packages/api-client/      从 OpenAPI 生成的客户端与类型
docs/product/             范围、用户流程、验收场景、迭代记录
docs/design/              Token、组件映射、Figma 链接
docs/architecture/        数据模型、接口约定、关键决策 ADR
docs/superpowers/specs/   本设计及后续修订
infra/                    Compose 与本地运行示例
```

本地开发使用前端 dev server + API + PostgreSQL；Compose 提供数据库及完整应用启动方式，数据库命名卷持久化，`.env.example` 不含真实密钥。MVP 默认仅绑定本机，单工作空间、无登录；如果后续需要公网部署或多用户，须先增加鉴权与数据归属隔离。CORS 限定本地开发来源，不使用全放开作为默认配置。

## 8. 数据模型与一致性

| 实体 | 核心信息与关系 |
| --- | --- |
| Settings | 单例；每日预算、学习日、IANA 时区 |
| Topic | 目标、优先级、active/paused/archived、创建时间 |
| Resource | topic_id、链接或摘录、标题、来源、阅读状态 |
| Task | topic_id、可选 resource_id、标题、预计时长、顺序、可选计划日期、待办/完成、完成时间 |
| Note | topic_id、可选 resource_id、标题、Markdown、版本、更新时间 |
| ReviewCard | topic_id、可选 note_id、问题与答案快照、阶段、due_at、暂停标识、版本、策略版本 |
| ReviewEvent | card_id、评分或重置、发生时间、前后排程、幂等键；追加保存 |
| TaskCompletion | task_id、发生时间、当时本地日期、预计时长快照；任务仅完成一次，首版不支持重新打开，重复完成不能重复计数 |
| DailyOverride | 本地日期、项目类型与 ID、加入或跳过；同日同项唯一 |

主键默认 UUID；创建与更新时间使用带时区时间戳，服务端生成。跨实体引用校验同一主题，避免笔记引用到其他主题的资料。卡片保留问答快照，来源笔记更新不静默覆盖卡片。笔记使用版本号检测覆盖冲突，未保存内容离页提醒并保留本地临时草稿，手动保存才算持久化成功。

第一版对主题、已有内容的笔记、资料及任务以归档/软删除为主，不级联物理删除历史；隐藏资料不删除关联笔记，隐藏笔记不删除卡片，已隐藏来源显示“来源已归档”。归档主题优先于子项状态，所有相关项退出今日建议与复习。对外导出含主题内这些实体及策略版本、时间元数据，第一版只导出不导入，不将其称为已验证的恢复方案。数据库备份恢复另提供 `pg_dump`/`pg_restore` 操作说明，并在交付时实际演练一次。

## 9. 验收与验证

- 主题 → 资料 → 任务 → 笔记 → 问答卡 → 复习反馈 → 下一次排程可完整走通，重启后保持。
- 今日建议符合排序、预算、学习日、超额提示、跳过与恢复规则；无任务、全归档、全未来日期都提供可操作空态。
- 三种评分、首次复习、阶段上限、逾期、10 分钟重试、时区及午夜边界由可注入时钟的服务测试验证。
- 反馈重试不重复排程，多标签页旧版本不能覆盖新状态；笔记保存冲突与网络失败有可恢复交互。
- 真实 PostgreSQL 上验证迁移、关联约束、事务与导出；空库能升级至最新版本，记录备份恢复步骤。
- 用浏览器端到端场景覆盖完整闭环，键盘可以操作核心流程；按钮有可访问名称，状态不只靠颜色表达，手机宽度无阻断操作的溢出。
- CI 运行前端类型检查/构建、后端测试、API 契约检查及关键端到端场景。只围绕真实风险写测试，不为纯展示组件堆快照。

第一版只显示完成任务数、复习次数、到期卡数及计划估时，不展示无法可靠测量的“掌握率”“专注时长”。通过一周试用记录计划调整原因、复习积压及使用阻力，再决定算法或交互升级。

## 10. 迭代交付顺序

1. **设计基线**：确认本范围；完成 Figma 核心流程、设计变量、组件映射及异常状态。出口：可点击演示完整学习闭环。
2. **纵向闭环**：数据库迁移、API 契约、前端框架及主题/资料/任务/笔记/复习的最小可用流程。出口：数据实际保存且能重启。
3. **今日安排**：实现预算与确定性建议、跳过/手动加入、设置、搜索和导出。出口：无需自己每天重排计划即可开始。
4. **打磨与试用**：补齐异常状态、响应式、关键测试、本地启动和备份恢复文档；真实试用一周。出口：已知问题和下一版优先级有记录。

每个增量都是可运行、可验收的功能，数据库变更只通过迁移落地，需求修改记录原因与验收差异。优先保持单体后端与清晰模块，避免为未来迭代引入当前不需要的基础设施。

后续候选顺序由实际使用反馈决定：PDF/文件收集 → 复习算法升级 → AI 辅助出题 → 公网账户/跨设备 → 更丰富的学习分析。它们均不构成第一版承诺。
