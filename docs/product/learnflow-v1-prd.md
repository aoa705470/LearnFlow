本文将学习主题、资料、任务、笔记与间隔复习整合为可实施的第一版需求。目标是让个人学习者每天知道从哪里开始，能找到已收集的资料，并持续复习自己整理的知识。

功能范围沿用已确认的设计草案。个人本地使用、中文界面、默认每天 45 分钟、工作日学习、Asia/Shanghai 时区是当前设计默认值，不代表用户逐项确认；学习偏好可在设置中修改。本文不新增第一版功能承诺。

## 1 产品背景与目标

### 1.1 需要解决的问题

| 用户问题 | 具体表现 | 第一版应提供的能力 |
| --- | --- | --- |
| 学习资料分散 | 链接、课程与摘录分布在多个地方，难以再次找到 | 按主题集中资料，支持搜索与阅读状态 |
| 学完容易忘 | 笔记写完后很少再看，缺少主动回忆 | 从笔记制作问答卡，到期后进行间隔复习 |
| 每天不知道学什么 | 每次开始前都要重新选择和规划 | 根据计划学习时间、任务顺序和到期复习生成今日建议 |

### 1.2 产品定位

面向自主学习新知识的个人学习者，提供一个以行动和回忆为中心的学习工作台。第一版围绕一个工作空间展开，适合同时维护多个学习主题。

核心闭环：**创建主题 → 收集资料 → 拆分任务 → 今日学习 → 保存笔记 → 制作复习卡 → 到期回忆 → 根据反馈安排下一次复习。**

资料阅读、任务完成、笔记保存与复习反馈是独立动作。收藏资料不代表学会，完成任务不代表记住，创建卡片也不是完成任务的强制条件。

### 1.3 成功标准

- 用户能围绕一个真实主题完成全部闭环，关闭浏览器和重启服务后数据仍然存在。
- 每天进入首页即可看到可解释、可直接开始的建议，或明确的下一步空态提示。
- 复习记录及下次时间准确保存，网络重试不会重复计数。
- 连续试用一周，记录每日是否需要额外规划、跳过原因、复习积压和使用阻力，据此决定下一版优先级。

第一版不承诺特定记忆提升比例，也不以笔记数量、收藏数量代表学习效果。

## 2 用户场景与范围

### 2.1 典型使用场景

1. **准备学习**：创建“Vue 3 入门”主题，写下“独立完成一个带接口的页面”的目标，添加文档链接，拆分若干 20～30 分钟的任务。
2. **每天开始**：打开今日学习，看到到期卡片与适合剩余时间的任务，理解推荐原因后直接开始。
3. **整理知识**：在任务对应笔记中记录理解与示例，从选段预填答案，再手写一个需要主动回忆的问题。
4. **巩固记忆**：先看问题、自行回忆，再显示答案并选择“忘记、模糊、记住”，看到下一次复习时间。
5. **调整节奏**：当天时间不足时修改计划时间或跳过建议；暂停某个主题时，其任务和复习卡暂时退出推荐。

这些需求进入候选池，是否实施取决于真实使用反馈，不构成本版交付承诺。

## 3 信息架构与页面职责

一级导航包括今日学习、学习主题、资料库、知识笔记、复习；设置作为次级入口。

| 页面 | 用户需要完成的动作 | 关键状态 |
| --- | --- | --- |
| 今日学习 | 查看计划时间、了解推荐原因、开始任务或复习、调整当天安排 | 首次使用、无可推荐任务、计划时间用完、超计划时间、完成、加载失败 |
| 主题列表与详情 | 创建主题、编辑目标、管理资料和任务、查看笔记与卡片 | 空主题、活动、暂停、归档、保存失败 |
| 资料库 | 添加资料、搜索、筛选、修改阅读状态、打开来源 | 空列表、无搜索结果、无效链接、来源已归档 |
| 笔记列表与编辑 | 编辑和预览 Markdown、保存、搜索、制作问答卡 | 未保存、保存中、已保存、失败、版本冲突 |
| 复习界面 | 回忆问题、展示答案、提交反馈、查看下一次时间 | 无到期卡、提交中、失败、版本冲突、等待重试 |
| 设置与导出 | 修改偏好、导出主题或笔记 | 校验失败、保存中、导出中、失败 |

完整产品需实现上述页面职责。Figma 已重做为精简核心原型 v2，展示主要学习流程和必要管理操作，不再穷举所有异常与条件组合。原型采用预设输入与示例状态，真实数据、任意输入和完整业务验收仍需开发；当前入口见 docs/design/README.md，边界见 docs/design/prd-figma-coverage.md。

## 4 功能需求

### 4.1 LF-01 学习主题

- 创建主题时填写标题、学习目标和优先级；标题必填，目标用于说明希望获得的能力。
- 主题详情集中展示所属资料、任务、笔记与复习卡，任务支持主题内顺序调整。
- 主题状态为活动、暂停、归档。暂停后保留可编辑内容，但其任务和卡片不进入自动推荐；归档后只读并退出推荐及复习队列。
- 恢复主题后保留任务和卡片原始状态、复习到期时间及历史，不重新计算成“新知识”。
- 暂停与归档主题均恢复为活动；不恢复归档前主题状态。归档资料只读，可在主题非归档时恢复，保留阅读状态与关联。
- 主题有历史内容时以归档方式退出日常视图，不级联物理删除历史。
- 主题状态变更成功后，相关列表、详情、来源摘要、今日与复习缓存共同失效；保留列表上下文及未保存输入，归档/恢复的成员变化以重取结果为准，按API第11节执行。

**验收**：暂停一个有到期卡的主题后，首页建议与复习队列均不再出现其内容；恢复后逾期卡重新可见，历史记录保持。

### 4.2 LF-02 资料库

- 资料属于一个主题，包含标题、类型、来源描述与阅读状态；链接类型保存 URL，摘录类型保存文本内容。
- 支持按关键词查找资料，按主题和阅读状态筛选；无结果时保留查询条件并提供清空入口。
- 链接仅接受可安全打开的 HTTP 或 HTTPS 地址，外部资料在新标签页打开。第一版不自动下载、抓取或解析内容。
- 阅读状态由用户手动调整，任务完成不自动修改阅读状态。
- 归档资料后保留关联关系，笔记仍可访问并显示来源已归档。

**验收**：新增链接和文本摘录均可刷新后再次查到；无效 URL 显示字段错误并保留其他已填内容。

### 4.3 LF-03 学习任务

- 每个任务包含所属主题、标题、正整数预计分钟数、主题内顺序、可选计划日期和可选关联资料。
- 计划日期为1000-01-01～9999-12-31（含边界）的真实公历日期，严格使用YYYY-MM-DD或null；非法格式、日历日期及越界值在写入前返回422字段错误。该范围仅匹配既有MySQL存储能力，不改变过去/未来任务的排程规则；省略、清空语义见API。
- 任务由用户手动拆分，不根据资料自动生成。没有任务时引导先创建一个可执行的小任务。
- 任务状态为待办或完成；开始学习提供资料与笔记入口，不自动宣告完成。
- 用户确认完成后保存完成事件与预计分钟数快照。重复提交完成不重复记账；第一版不支持重新打开已完成任务。
- 已完成任务仅允许修改标题和关联资料，仍参与主题内排序；不修改估时、计划日期、完成状态或历史快照。
- 开始任务时，有资料则进入该资料的关联笔记列表，无资料则进入主题笔记列表；用户选择已有笔记或新建，不自动指定第一篇。
- 当天跳过只改变当天建议，不将任务标记为完成，也不修改其计划日期。

**验收**：完成一个预计 20 分钟的任务后，当日已用计划估时增加 20 分钟；之后修改其他任务或刷新页面，不改变该完成快照。

### 4.4 LF-04 知识笔记

- 支持标题、Markdown 正文、所属主题与可选关联资料，提供编辑和预览。
- 使用手动保存。只有服务端保存成功才显示“已保存”；失败保留编辑内容并提供重试。
- 离开存在未保存修改的页面时提醒；本地临时草稿用于降低意外丢失风险，不替代服务端持久化。
- 按标题或正文关键词搜索，支持中文内容。
- 保存携带版本号；多标签页编辑产生冲突时阻止静默覆盖，保留本地文本，允许用户查看最新版本后重新整理保存。
- 从已保存笔记选段可以预填复习卡答案，问题由用户填写。笔记可独立保存，无需创建卡片。

**验收**：断网保存不会出现成功提示，恢复连接可重试；两个页面编辑同一版本时，后提交的旧版本不得覆盖已保存的新版本。

### 4.5 LF-05 复习卡片

- 卡片包含所属主题、问题、答案和可选来源笔记；问题和答案必填，一张卡聚焦一个回忆点。
- 卡片保存问答快照，修改来源笔记不静默覆盖卡片内容。
- 新卡立即到期。创建卡片与立即进入复习可以连续操作，也可以之后再复习。
- 支持编辑、暂停和恢复。编辑答案不自动重置历史；重置必须是明确操作，并生成重置事件。
- 重置后阶段恢复为 -1，立即到期。存在任一评分或重置事件的卡片不可永久删除，可通过暂停退出队列；只有无任何历史事件的卡片允许删除，包括从未评分但已重置的卡片也须保留。

**验收**：更新笔记后卡片答案保持原快照；主动重置后仍能追溯旧复习记录。

### 4.6 LF-06 间隔复习

- 队列只包含活动主题中未暂停且已经到期的卡片，按到期时间升序、卡片 ID 排序。
- 初始只展示问题；用户主动展示答案后才能评分。展示答案不修改排程，离开未评分卡不计完成。
- 评分为“忘记、模糊、记住”，具体规则见第 6 节。
- 提交中避免重复操作，提交失败保留当前卡和重试入口；成功后显示下次时间并允许继续或返回首页。
- 无到期卡时显示完成状态；若有等待中的卡片，可显示最近一次复习时间，不要求用户留在页面等待。
- 首版不提供评分撤销。

**验收**：一次评分成功只生成一条反馈事件；同一请求因网络重试到达多次，不重复推进阶段。

### 4.7 LF-07 今日学习

- 展示今日计划时间、已完成任务、复习次数、计划估时与到期卡数量。
- 每条建议展示预计分钟数和可理解的理由，例如“已到复习时间”“计划日期已到”“当前主题优先级较高”。
- 支持开始、完成任务、加入当天安排、今天跳过和恢复。手动加入遵循主题活动状态与任务未完成等资格校验，不突破归档或暂停限制。
- 计划学习时间是建议，不阻止用户超额学习；超额必须明确标注。
- 今日建议根据当前数据计算，完成记录保留，不能因刷新或重算消失。具体排序与计划时间规则见第 5 节。

**验收**：刷新后当天跳过仍生效，下一天自动失效；没有任务时提供创建入口，不生成虚构计划。

### 4.8 LF-08 学习设置

- 支持每日学习时间、每周学习日和 IANA 时区设置。默认计划时间 45 分钟，范围 5～1,440 整数分钟；学习日允许空集合，表示只手动学习，到期复习仍可查看。字段边界统一见 FEATURES.md 第 2 节。
- 偏好保存成功后重新计算今日建议，不修改已有学习和复习事件。
- 非学习日不自动推荐新任务，但仍可查看到期复习并手动学习。
- 时间存储与时区规则见第 7 节。不得把浏览器时区变化静默当作用户修改偏好。

**验收**：计划时间从 45 分钟改为 30 分钟后，建议依据剩余计划时间重算；历史完成数不减少。

### 4.9 LF-09 数据导出

- 支持主题数据 JSON 导出，包含主题内资料、任务、笔记、卡片、学习与复习记录，以及策略版本和必要的时间元数据。
- 支持笔记 Markdown 导出，保留标题与正文。
- 导出中显示状态，失败显示原因并允许重试，不下载不完整结果冒充成功。
- 第一版无应用内导入；导出不等同于已验证的恢复能力。数据库备份恢复另提供操作说明并演练。

**验收**：导出内容可解析，与主题内记录相符；包含中文、换行和 Markdown 符号的笔记保持可读。

## 5 今日安排规则

### 5.1 计划时间计算

设每日学习时间为 B，当日完成任务的预计分钟数快照合计为 T，当日成功提交的复习反馈次数为 C。

```text
已用计划估时 U = T + 2 × C
剩余计划时间 R = max(0, B - U)
有效手动加入任务估时合计 M = 去重后的有效 include 任务估时之和
自动可用时间 A = max(0, R - M)
```

每次复习按 2 分钟估算；这些数值用于安排时间，不显示成真实专注时长。重置事件不属于复习反馈，不增加 C。

有到期卡时，复习建议最多使用每日学习时间的 40%，在剩余计划时间允许时至少容纳 1 张。将既有规则具体化为下式，避免取整和完成后补充策略产生歧义：

```text
若 A < 2：建议复习张数 N = 0
否则：N = min(可推荐到期卡数, floor(A / 2), max(1, floor(B × 0.4 / 2)))
任务可用计划时间 = A - 2 × N
```

可推荐到期卡不包含今天已跳过项。超过建议数量的到期卡仍显示为剩余待复习数量，用户可从完整队列继续。没有到期卡时，全部自动可用时间用于任务。40% 限制每次重算的复习建议，不限制当天累计复习；完整合并、排序、超额与去重规则以 FEATURES.md 第 9 节为准。

### 5.2 任务选择顺序

1. 仅考虑活动主题的待办任务，排除今天跳过项、已手动加入项和未来计划日期任务。
2. 先选计划日期不晚于今天的任务，较早日期优先；其后是没有计划日期的任务。
3. 同组内按主题优先级降序、主题创建时间升序、主题内顺序升序、任务 ID 升序排序。
4. 依次扫描，选择能放入任务可用计划时间的项目；放不下的仍保留在待办。
5. 如果没有任何任务能放入，但任务可用计划时间仍大于零，展示排名最前的一项并标明预计超计划时间，由用户决定开始或拆分。

任务顺序不代表前置依赖。第一版不推断依赖；需要严格先后的内容由用户通过计划日期与任务调整管理。

### 5.3 手动调整与日界线

- 手动加入和跳过按用户本地日期保存，同日同项只保留一个有效覆盖状态。用户明确加入后可超过计划时间，但要展示超额提示。
- 手动加入支持活动主题的待办任务，包含未来计划日期任务，不改原日期。先占预算，再自动分配；手动项在任务区置前，按最近加入时间（include覆盖updated_at）和ID排序，同项去重，重复同action不改顺序。卡片只支持当天跳过与恢复，额外复习使用完整队列，不支持card include。
- 完成或主题不再活动使手动加入暂不生效、不重复占预算，覆盖记录不因重算删除。非学习日保留有效手动任务和可选复习，停止自动任务推荐。
- 恢复跳过项意味着撤销当天跳过覆盖，不修改原任务日期或卡片 due_at。
- 非学习日不自动安排新任务；到期复习作为可选内容展示，手动学习仍可进行。
- UTC 事件按当前设置时区计算当日归属。修改时区后当日统计重新计算；历史事件保留发生时本地日期以便追溯。
- 当天覆盖记录保留其原始本地日期，时区变更不改写这些记录；仅与当前本地日期匹配的记录生效。

### 5.4 计算示例

计划时间 45 分钟、当日尚无完成记录、2 张到期卡、2 个任务分别预计 20 和 15 分钟：复习占 4 分钟，任务占 35 分钟，剩余 6 分钟未分配。

计划时间改为 30 分钟时：复习占 4 分钟，先选 20 分钟任务，15 分钟任务保留待办，剩余 6 分钟未分配。原型中的“弹性时间”即未分配计划时间，并非额外预留规则。

## 6 间隔复习规则

本版采用自定义固定间隔策略，不称为 SM-2 或 FSRS。策略名称和版本随事件保存，便于以后替换算法。

阶段为 -1、0、1、2、3、4、5；新卡阶段 -1。阶段 0～5 的间隔分别为 1、3、7、14、30、60 天。

| 用户反馈 | 阶段变化 | 下次到期时间 |
| --- | --- | --- |
| 记住 | 当前阶段加 1，最大为 5 | 提交成功时间加新阶段对应天数 |
| 模糊 | 保持当前阶段 | 提交成功时间加 1 天 |
| 忘记 | 重置为 -1 | 提交成功时间加 10 分钟 |

- 新卡首次“记住”进入阶段 0，1 天后到期；再次“记住”进入阶段 1，3 天后到期。
- 阶段 5 再次“记住”仍为 60 天后；新卡“模糊”仍保持 -1。
- 天按固定 24 小时计算，基于服务端 UTC 时间加时长；界面转换为用户时区显示。
- 逾期不自动重置阶段、不隐藏卡片；提交反馈后，从本次实际提交时间计算下一次，而非旧到期时间。
- 卡片满足 due_at ≤ 当前时间即到期，服务端按查询时刻判断，不依赖浏览器常驻或后台定时任务。
- 每次提交包含唯一幂等键与卡片版本。同一卡反馈事务串行处理；重复请求返回原结果，旧版本请求返回冲突并刷新状态。
- 复习事件保留评分、发生时间、原阶段、新阶段、下次时间、策略版本和幂等键。

## 7 数据关系与生命周期

| 对象 | 关键内容 | 关系与约束 |
| --- | --- | --- |
| 学习设置 | 计划时间、学习日、时区 | 当前工作空间唯一配置 |
| 主题 | 标题、目标、优先级、状态 | 资料、任务、笔记、卡片的归属 |
| 资料 | 标题、链接或摘录、来源、阅读状态 | 属于一个主题 |
| 任务 | 标题、预计分钟、顺序、计划日期、状态 | 属于主题，可关联同主题资料 |
| 笔记 | 标题、Markdown、版本、更新时间 | 属于主题，可关联同主题资料 |
| 复习卡 | 问答快照、阶段、到期时间、暂停、版本 | 属于主题，可关联同主题笔记 |
| 复习事件 | 评分或重置、前后排程、幂等键、策略版本 | 追加记录，不被内容编辑覆盖 |
| 任务完成事件 | 发生时间、本地日期、预计分钟快照 | 一个任务最多一次有效完成 |
| 当日覆盖 | 本地日期、项目类型、项目 ID、加入或跳过 | 同日同项唯一 |

跨对象引用必须属于同一主题。主键使用 UUID；服务端生成创建和更新时间，时间戳以 UTC 保存并按设置时区显示。计划日期与当日覆盖日期是本地日历日期，不当作 UTC 时间戳使用。

第一版提供主题归档及资料自身归档/恢复；任务和笔记随主题归档变为只读，不增加独立归档、恢复或删除入口，其 archived_at 仅预留存储能力。不通过级联删除丢失学习历史，资料归档不删除笔记或复习卡；来源仍可查看并显示归档状态。主题归档状态优先于子项状态。

资料、任务、笔记、卡片全局列表默认隐藏归档主题的内容，支持主题状态筛选；归档主题详情仍可只读查看全部内容。已归档资料入口默认跨全部主题，资料自身归档与主题归档是两个独立筛选维度。具体过滤默认值见 API.md，返回保留筛选上下文。

查看资料关联笔记/任务及笔记关联卡片时，列表请求同时携带该来源的topic_id和关联ID，省略主题状态条件按all，避免归档主题内已有内容被误报为空；不改变全局列表默认值或只读限制。

## 9 技术约束与非功能需求

### 9.1 技术组合

- 前端采用Vue 3、TypeScript、Vite、Vue Router；UI组合为shadcn-vue + Reka UI + Lucide，配合Tailwind CSS、自定义业务组件和Figma Design System。职责与实现约定见 docs/design/ui-architecture.md。
- 后端语言采用 Python，Web 框架采用 FastAPI，数据访问采用 SQLAlchemy，数据库采用 MySQL，结构变更通过 Alembic 迁移维护。
- 按主题、资料、任务、笔记、复习、今日安排、设置和导出划分模块，使用模块化单体，不引入当前不需要的微服务或队列。
- REST API 使用 /api/v1；由 OpenAPI 生成 TypeScript 类型或客户端，降低前后端契约漂移。
- 具体依赖版本与兼容性在实现时核查、锁定，本 PRD 不固定未经验证的版本号。

### 9.2 数据与运行保障

- 默认本机单用户、单工作空间、无登录，服务仅绑定本机；公网或多用户部署属于后续范围，需另行设计鉴权和数据隔离。
- development允许本机Uvicorn直连和Vite代理；production指本机交付，通过Nginx回环入口访问，API仅在内部容器网络提供业务服务、不发布宿主机端口。两种环境的Host/Origin、调试及健康检查按API第1.1节配置，开发模式不关闭安全校验。
- MySQL 使用 InnoDB 事务引擎和 utf8mb4 字符集；应用统一写入 UTC 时间，连接会话统一使用 UTC，按用户设置时区展示。数据持久化，重启不丢失；提供空库迁移、本地启动、配置示例及备份恢复步骤。
- Markdown 禁用原始 HTML 或进行等效安全处理，限制外链协议；API 校验输入，搜索使用参数化查询。
- 统一错误结构包含可读信息、错误码、字段错误及请求 ID，页面不能只显示不可理解的异常堆栈。
- 列表分页，避免一次加载全部记录；请求中有加载反馈，错误可恢复。性能目标与基准环境记录门禁见实施就绪记录，当前未测量，不作为已验证指标。
- 真实 MySQL 上验证事务、关联约束和迁移；提供 mysqldump 导出与 mysql 导入恢复说明，数据库备份恢复至少实际演练一次。
- 用户确认备份至少每日一次，重要操作前另备份，保留7份日/4份周备份，恢复目标≤30分钟；按DATABASE第8.3节人工执行，不增加后台调度，实际恢复达标仍待演练。

### 9.3 迭代能力

- 复习算法独立封装并持久化策略版本；升级时明确历史卡片迁移方案。
- 基础 UI 组件与学习业务组件分离，设计 Token 与代码统一映射。
- 数据库变化通过新增迁移完成；API 契约检查纳入持续集成。
- 需求变更同步更新本文、验收场景与设计差异，不以修改原型替代产品规则更新。

## 11 指标与试用反馈

第一版仅展示可可靠解释的数据：完成任务数、成功复习反馈次数、当前到期卡数和计划估时。复习次数是有效反馈事件数：同一卡再次到期后的新评分可再次计数；同一评分请求的网络重试只计一次。不与“复习卡片去重数”混用。

不显示未经测量的掌握率、真实专注时长或记忆提升比例。首轮试用连续观察一周，收集以下反馈即可，无需引入外部埋点服务：

- 打开今日学习后是否知道下一步，是否频繁手动重排。
- 跳过任务或复习的原因：时间不够、内容不合适、任务过大或其他。
- 复习积压是否持续增加，计划时间分配是否挤压新学习。
- 资料到笔记、笔记到卡片的操作是否顺畅。
- 保存失败、数据丢失、统计错误等问题及复现条件。
